# Windows 便携预览的构建与发布

支持目标：Windows 11 x64，Edge/Chrome。程序与数据分离，发行包包含 Node 24.10.0、生产服务和离线 WASM/NumPy，不需要用户安装开发环境。项目代码采用 [MIT](../LICENSE)；第三方许可随发行包保留。

## 使用发行包

下载 Releases 中的 ZIP 和 `.sha256`，核对 hash，完整解压到固定的可写目录，双击 `start.cmd`。安装说明见 [README-安装说明.md](../packaging/portable/README-安装说明.md)。应用在服务就绪后自动开浏览器；停止使用 Ctrl+C。

默认从 PATH 检测 agy，可在便携目录 `portable-settings.json` 填写 `agyPath` 的完整路径。用户自行安装、登录 agy；当前仅验证 1.2.11。环境设置页显示已填好的 PowerShell MCP 注册命令，注册和额度探针均由用户主动执行。

数据始终保存在 `%USERPROFILE%\.herta-ai\adaptive-tutor-platform\`。更新前停止应用并冷备份数据目录，保留 portable-settings.json；不要混合覆盖不同版本的 node_modules。移动安装目录后需要更新 MCP 注册。

## 本机构建

固定 Node 24.10.0 和 pnpm 11.25.0。在 Windows x64 仓库根目录执行：

```powershell
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm package:win --version 0.1.0-alpha.1
pnpm verify:portable --zip releases/adaptive-tutor-platform-v0.1.0-alpha.1-win-x64.zip
pnpm test:e2e
```

打包命令自动运行生产构建和 NumPy 准备。之后在独立 `.release-work/package-*` 目录使用锁文件执行 `install --prod --frozen-lockfile --ignore-scripts`，采用 hoisted 布局，不裁剪开发机依赖。core-js 安装期脚本显式禁用，发行 staging 中所有安装脚本均禁用；不引入 node-gyp。

Node 官方 ZIP 版本、下载地址和 SHA-256 固定在 `packaging/node-runtime.json`，先校验再解压；升级 Node 时需同时更新 `.node-version`、该文件及兼容验证记录。构建工具版本也固定在 package.json。首次打包需要网络，之后仍可能需要下载未缓存依赖；**运行发行包的离线功能不需要网络**。

`releases/` 生成：

- `adaptive-tutor-platform-v<版本>-win-x64.zip`
- 同名 `.zip.sha256`
- 同名 `.manifest.json`，记录源码提交、工作区是否有未提交内容、Node/pnpm 版本及所有文件 hash。
- 验证后生成同名 `.zip.verification.json`，记录实际结果及待人工项目。

版本必须是预览版本，且不会覆盖已有同名 ZIP。需要重建时先把旧产物移到其他目录，或使用新预览版本。`--skip-build` 只供已完成生产构建的本地调试，不应用于正式发行。

产物显式包含 `dist`、生产 `.next`、`.runtime-build`、生产依赖和许可，排除 `.next/dev` 与构建缓存。不使用 Next standalone，也不把用户数据目录复制进包。应用自己代码的 MIT 不替代 Pyodide 的 MPL 或其他依赖条款；许可来源/hash、依赖清单及 NumPy wheel 中的许可一起分发。

## 最终 ZIP 验证

`verify:portable` 校验 ZIP hash、逐文件清单以及没有符号链接；解压到系统临时目录中的中文/空格路径，以包内 Node 启动应用。子进程使用隔离 USERPROFILE/HOME、裁剪后的 PATH 和不同 cwd；不会读写真实用户的课程数据。

Edge 自动化阻断非回环页面请求，验证首页、离线状态、实际 MCP 路径和 JS/SQL/Python/NumPy 计算；再验证强杀后重启以及合成 SIGINT 清理。测试不启动真实 agy，不消耗用户额度。测试后的临时目录保留以便诊断，里面仅有临时测试数据。

这些自动化不等于完成干净 Windows 的人工安装验收、实际键盘 Ctrl+C、自动浏览器体验、真实 agy 注册或整阶段性能/科学复核。公开前仍应按报告中的 manualPending 检查。

## GitHub Releases

`.github/workflows/windows-portable.yml` 支持：

1. 在 GitHub Actions 手动运行 `Windows portable preview`，填写 `0.1.0-alpha.1` 之类的版本；或推送 `v0.1.0-alpha.1` / beta / rc tag。
2. Windows runner 安装固定工具、执行类型检查与测试、构建 ZIP、验收最终解压包，再跑浏览器回归。
3. 全部通过后上传 Actions artifact，并创建 **draft + prerelease** 的 GitHub Release。人工复核后从 GitHub 页面公开草稿；流水线不会自动把预览标为稳定版。

工作流需要仓库启用 Actions，发布 job 具有 contents:write。相同 tag 已有 Release 时创建步骤会失败，不覆盖旧文件；使用新的预览版本或人工处理已有草稿。公开 CI 不带维护者 agy 凭证，也不自动运行模型联调。GitHub 自动附带 tag 对应的源码下载；不要用包含未提交改动的本机 ZIP 冒充干净 tag 产物。

正式公开前复查固定 Node/Next 的安全维护状态、许可、首次安装和更新/恢复。当前为开发预览，完整一期缺口继续记录在 [remaining.md](../specs/phase-1/remaining.md)；不能把可安装等同于一期验收完成。
