# 本地应用发布方案调研

调研日期：2026-09-27。基于提交 `1f89fe9`、现有 PRD/技术设计、本机构建产物及下列官方资料。下文保留调研时的设计与缺口；后续实现和实际命令请看 [便携版发布](便携版发布.md)，验证记录见 [发行追踪](../specs/phase-1/M5/portable-release.md)。

## 建议

首先提供 **Windows 11 x64 便携 ZIP，通过 GitHub Releases 分发**。包内带固定 Node 24、生产依赖、前后端构建产物及离线运行库。用户解压到可写的固定位置，双击启动，在 Edge/Chrome 中使用。用户无需安装 Node、pnpm、Git、Python 或 C++ 构建工具；不修改其他项目的环境。

在线导师仍要求用户自行安装、登录 Antigravity CLI。应用不分发其登录信息，不代装 CLI。未配置时可使用本地示例、实验和已有课程。

第一份公开构建建议标为 `v0.1.0-alpha.1` 开发预览，清楚列出现有功能和缺口；完整一期仍按 A01～A30 验收，不能因可以下载就标记一期完成。首批支持范围为 Windows 11 x64；ARM64、macOS、Linux 需要分别构建和验证。

| 方式 | 用户需要做什么 | 与本项目的匹配程度 |
| --- | --- | --- |
| Windows 便携 ZIP | 解压、启动；在线功能另行配置 agy | 首选，保留现有本地架构，免构建工具 |
| 源码发行 | 安装 Node/pnpm、安装依赖、构建 | 保留给开发者，现有 README 已支持 |
| npm/npx 命令 | 安装 Node 24，联网下载包及依赖 | 可作为后续开发者入口；不等于免环境安装 |
| Windows 安装器 | 安装、桌面快捷方式 | 后续可封装相同产物；当前范围不增加原生安装器 |
| Electron/Tauri | 安装桌面程序 | 需要额外生命周期、打包及浏览器兼容工作，当前无必要 |
| Docker/云部署 | 配置容器、存储、CLI 登录与网络 | 与本人已登录 CLI、回环服务的当前设计不匹配 |

## 已核实的发布约束

1. `src/server/main.ts` 是生产入口，承担数据目录、单写锁、HTTP 服务和退出清理；`src/server/http.ts` 承担 API、SSE、MCP 网关与代码运行库。必须保留这套服务，不能用 `next start` 替代。
2. Next.js 官方明确说明：standalone 不追踪自定义 server，生成的是另一个最小 `server.js`，两者不能直接结合。不能只加 `output: 'standalone'` 就宣称完成打包。第一版使用完整的生产依赖目录；后续若裁剪，需同时追踪自定义 server、MCP、Next 及动态资源，并在无源码环境验证。
3. `.runtime-build/` 是运行时必需内容，HTTP 服务按相对编译入口的路径读取它；`dist/` 只是服务端编译结果，不是独立应用。
4. 当前 agy 检测只接受版本字符串 `1.2.11`，且仅搜索 PATH。其他人安装的新版可能被拒绝，双击启动的 PATH 也可能与开发终端不同。应增加明确的可执行路径选择、重新检测和已验证版本列表；未经联调不能直接放开所有版本。
5. MCP 当前使用 Node 与 `dist/mcp/stdio.js` 的绝对路径。移动应用目录会使注册失效，升级流程必须保持稳定路径或引导重新注册。
6. `package.json` 标记 `private: true`，没有 `bin` 或发布文件白名单；直接 npm 发布不可行。`.gitignore` 排除了 `.next`、`dist`、`.runtime-build`，直接套用默认打包规则有遗漏产物的风险。
7. 仓库没有项目 `LICENSE`、第三方许可汇总和 GitHub Actions 发布配置。需要维护者确定项目许可，并整理 Node、Next、Python/Pyodide、NumPy、SQLite/WASM、QuickJS 等实际分发内容的许可。
8. 项目已经排除 sharp；SQLite 使用 `node:sqlite`。继续禁止引入需要 node-gyp 的包，Next/SWC 等平台预编译组件应在构建机准备，不能依赖用户现场编译。

## 建议的用户体验

1. 下载 `adaptive-tutor-platform-v0.1.0-alpha.1-win-x64.zip`，解压到固定、当前用户可写的目录。
2. 双击“启动学习工作室.cmd”。启动器显式调用包内 Node，设置当前子进程的生产环境，等待本地服务就绪后自动打开一次性引导链接。失败时保留可读错误，不能一闪而过。第一版可保留终端，退出用 Ctrl+C。
3. 设置页显示 agy 的实际检测结果；允许选择 CLI 路径。缺失时仍可进入离线功能。
4. 设置页生成本机可直接复制的 MCP 注册命令，指向包内 Node 和适配器；由用户执行或明确确认后注册。检查同名配置，避免覆盖其他配置。连通性探针由用户主动启动，并说明会使用额度。
5. 重复启动应提示已有实例；若支持直接打开已运行应用，需要增加受保护的本地启动器通信来申请新 token。不能把 MCP 凭证拿来当浏览器登录凭证。

当前第 2～4 项尚未实现为完整安装引导：启动入口仅打印链接，MCP 设置使用占位路径，CLI 没有文件选择功能。

## 产物布局与制作方法

建议保留安装根目录，更新时替换内部版本文件，MCP 不直接绑定带版本号的下载目录：

```text
adaptive-tutor-platform/
  启动学习工作室.cmd
  README-安装说明.md
  release-manifest.json
  LICENSE
  THIRD-PARTY-NOTICES/
  runtime/
    node.exe
    LICENSE
  app/
    package.json
    next.config.mjs          # 发布专用配置，与源配置一致，避免现场转译
    dist/                   # 包含 server、mcp 及其引用模块
    .next/                  # 生产 server/static/清单；排除 dev 和构建缓存
    .runtime-build/          # worker、WASM、标准库、NumPy、manifest
    node_modules/           # 完整生产依赖，全部引用限于包内
```

如未来增加 `public/`，必须一起打包。不要直接搬运开发机的整个 node_modules；pnpm 链接可能依赖工作区或在 ZIP 解压后失效。候选方法是固定 pnpm 11.25.0，使用独立 staging 和 `deploy --prod --legacy` 准备依赖，再显式复制产物；该命令在当前版本的帮助中存在，但本仓库的实际 deploy、链接处理和离线启动仍需打包原型验证。必要时将依赖物化为普通文件；不能静默遗漏链接或文件。

更小的依赖追踪包留待后续。第一次发布优先保证脱离源码目录和 pnpm store 后可以运行。`next.config.mjs` 是建议新增的发布产物，不是当前已经存在的文件。

构建顺序：

1. 在干净 Windows x64 构建机使用固定 Node/pnpm 和锁文件安装；保留 node-gyp 禁用约束与平台预编译依赖策略。
2. 执行类型检查、单元/集成测试、生产构建，以及运行库准备。建议发行包默认包含经锁定 hash 验证的 NumPy，减少用户手动准备步骤。
3. 下载官方 Node 24 Windows ZIP，核对官方 SHA-256 后提取运行时和许可。现有验证版本是 24.10.0；本次官方索引显示最新 24.x 为 **24.21.0**，应先完成兼容与依赖安全检查，再固定到发布版本，不直接改变开发环境。Next 当前为 16.2.0，发行前也需要检查维护版本与安全公告。
4. 生成 staging、版本和资源清单，排除源码测试资料、个人数据、凭证、`connection.json`、锁文件、`.env`、开发缓存。
5. 对最终 ZIP 解压出的产物执行安装验收，测试不能借用仓库 node_modules、开发机 Node 或 pnpm store。
6. 生成 ZIP 的 SHA-256、第三方许可清单和发布说明，上传草稿 Release；通过人工复核后发布。后续可用 tag 触发 Actions，并在发布 job 前设置环境审批。普通 PR 仅构建、测试，不上传正式 Release。

本机体积测量（未压缩，不是安装包大小）：`.next` 907.5 MiB，其中 cache 617.6 MiB、dev 283.2 MiB；生产 server/static 约 6.4 MiB；`.runtime-build` 含 NumPy 约 15.9 MiB；`dist` 约 0.2 MiB。最终下载大小还包括 Node 和生产依赖，应以实际 ZIP 为准。不要将当前约 900 MiB 开发缓存打进发行包。

## 更新、卸载和数据

学习数据继续位于 `%USERPROFILE%\.herta-ai\adaptive-tutor-platform\`，与程序目录分离。便携指程序可解压运行，不代表课程跟随 U 盘移动。

初版建议手动更新：停止应用，使用一致性方式备份数据，保留固定安装路径并完整替换应用文件；不要在旧依赖目录中混合覆盖。启动时执行受版本约束的数据库迁移。旧应用拒绝更高版本数据库，因此“回退程序文件”不能自动等价为安全回滚；应使用兼容备份恢复。当前 `.learn` 尚未支持全部外部资源，不能拿它当完整升级备份的替代品。

卸载程序默认保留学习数据；是否删除数据由用户单独选择。MCP 注册的移除也需要明确提示。第一版不增加静默自动更新。
